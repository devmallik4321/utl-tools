### E. Authoritative Metric Semantics & Epistemic Boundaries

Strict accounting principles have been codified across the platform:
1. **Visits Definition**: "Visits" is an informal term. The official internal proxy is **GA4 Sessions (`ga4_sessions`)**.
2. **Users vs Sessions**: A user can generate multiple sessions; sessions and active users are distinct.
3. **Monthly Unique Users**: Summing daily active users produces duplicated observations. Authoritative monthly unique users requires a dedicated GA4 monthly query. For September 2026 MTD, the GA4 query returned **10 unique users**, while summed daily observations equal **37**.
4. **Search Impressions vs Visits**: An impression in Google search results is an exposure, not a visit or session.
5. **Zero vs Null**: `null` indicates unavailable data; `0` indicates an active source that measured zero occurrences.

### F. Persistent Telemetry Subsystem Implementation

Implemented in `intelligence/telemetry/persistentTelemetryStore.mjs`:
- **Storage Engines**: Pluggable architecture supporting `FileStorageEngine` (local durable file) and `UpstashRedisEngine` (serverless cloud REST).
- **Privacy Enforcement**: Intercepts payloads and rejects all forbidden keys (`password`, `token`, `secret`, `input`, `email`, `ip`, `payload`, etc.).
- **Deduplication**: In-memory and persisted Set index on `event_id` ensures replay protection and idempotency.
- **Retention**: Sliding 30-day window purges expired records automatically.
- **Aggregation Engine**:
  - `getUtilityAggregates()`: Aggregates views, executions, and execution conversion rate by tool slug.
  - `getTopUtilities(limit)` / `getBottomUtilities(limit)`: Fast ranking of utilities by interaction volume.
